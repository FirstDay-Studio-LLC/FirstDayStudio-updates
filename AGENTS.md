

## Standing autonomous execution rule (2026-11-26)

Do not wait for owner check-ins or routine manual input. Every execution must advance approved roadmap work: implement, repair, test, review, and integrate qualifying changes using the existing authorized release/deployment scope. Resolve ordinary conflicts, failed checks, branch divergence, stale claims, handoffs and runner problems independently. If blocked, advance another independent approved task, recording the blocker and next action. Escalate only a material product/scope decision or a concrete blocker that cannot safely be resolved with available access; do not stop unrelated work.

Standing authorization supersedes older owner-only routine merge/review/check-in instructions: agents may review and merge qualifying PRs independently after exact-head required checks and review gates pass, and publish eligible development/alpha releases using existing release mechanisms and verified post-merge gates. Do not bypass branch protection, tests, production launch gates, or existing explicit production deployment restrictions. If merging would itself deploy to production outside existing authorization, prepare the verified PR and continue independent work. No new production deployment authority. No logins, account creation, personal-data entry, purchases, destructive actions or third-party outreach; only escalate such genuinely necessary steps. Never claim success without evidence. Existing project-specific scope, security and data-integrity constraints remain binding.


## Shared multi-agent coordination (FirstDay portfolio)

Applies to ChatGPT, Claude, Gemini, Muse and other automated contributors. Preserve existing project-specific rules, priorities, authorization and release gates; resolve routine engineering conflicts independently and escalate only material scope changes or genuine unresolved blockers. No new deployment authority.

Before editing, refresh default branch, open issues/PRs/branches and docs/claims.json. Claim a unique issue, agent, branch, exact path prefixes, shared interfaces/migrations, acceptance tests and UTC expiry by compare-and-swap update of the registry on default branch using current blob SHA. On conflict reread and retry. Never edit without confirmed claim. Reject intersecting paths (including ancestors/descendants), shared contracts, migrations and cross-repo dependencies; acquire cross-repo claims in sorted repository order before editing. Treat existing active PRs/work as occupied until reconciled even if not registered. If registry inaccessible, retry, avoid unclaimed edits and advance independent safe work; escalate only persistent access blockers.

Use agent/<agent>/<issue> branches and one PR per claim. No force push or direct implementation edits on default branch. Renew before expiry; inspect PR/branch and record handoff before taking expired work. Record owner, scope, status, commit, tests and next action in issue/PR; release claim only after merge or documented abandonment. Do not edit another agent's work without explicit handoff. Owning agent fixes and reruns failed automated tests; do not weaken or bypass tests. Preserve release rules. Test on Vulcan/Qonos and optionally verified Romulus GUI runner, never Daedalus. This cooperative protocol does not prove automated enforcement; verify branch protection and CI separately.


## Mandatory evidence-based execution and reporting
- Discover available tools, verify access, attempt authorized operations and reasonable alternatives before reporting blockers. Record actual errors; escalate only necessary owner actions within authorization and security boundaries.
- Execute authorized work; preserve coordination, branch, testing and release safeguards. Do not repeatedly request already-granted approval.
- Provide exact commit/PR/file links and test evidence. Distinguish completed, attempted, pending, failed and unverified. Report exact-head tests, integration and independently verified deployed version; source publication is not deployment verification.
- Every progress report must include concrete changes, evidence, tests (passed/failed/not run), integration/deployment state, actual blockers and remedies, and necessary human action. Disclose assumptions, limitations and decisions not explicitly authorized. Never invent evidence or guarantee future execution or perfect compliance. Correct inaccurate reports promptly.
